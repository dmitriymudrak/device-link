# DeviceLink

Прототип шлюзу телеметрії для дронів на .NET 8. Симулятор дрона шле бінарні кадри по TCP на наземну станцію. Станція розбирає їх без алокацій і витримує кадри, розрізані, склеєні чи зіпсовані мережею.

## Стан

| Частина | Стан |
|---|---|
| `DeviceLink.Protocol` — кодек кадру, CRC16, повідомлення Telemetry | готово, покрито тестами |
| `DeviceLink.Simulator` — дрон, що летить маршрутом і шле телеметрію | готово |
| `DeviceLink.GroundStation` — приймає, розбирає й друкує телеметрію | готово |
| `DeviceLink.Api` — gRPC-бекенд, що збирає дані з багатьох станцій | далі |
| `DeviceLink.Viewer` — центральна консоль моніторингу | далі |

## Швидкий старт

Потрібен [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0).
Якщо версія відмінна від 9, потрібно буде редагувати файл run.ps1 та run.sh
```bash
# Windows (PowerShell)
./run.ps1

# Linux / macOS
./run.sh
```

Скрипт збирає рішення, запускає станцію, потім симулятор. Станція друкує рядок щосекунди:

```
14:20:01 seq=  0 lat=50.4501000 lon=30.5234000
14:20:02 seq=  1 lat=50.4505600 lon=30.5234400
```

`Ctrl+C` зупиняє обидва.

Запуск частин вручну:

```bash
dotnet run --project src/DeviceLink.GroundStation.Cli          # [порт], за замовчуванням 5000
dotnet run --project src/DeviceLink.Simulator                  # [хост] [порт], за замовчуванням 127.0.0.1 5000
dotnet test
```

## Архітектура

```
          Оператор у полі
                 │ команди (заплановано)
Дрон ──TCP──► Наземна станція ──gRPC──► Api ◄──gRPC── Viewer
     бінарні                  (заплановано)  (заплановано)
     кадри
```

- **Дрон ↔ станція:** один дрон на станцію, одне TCP-з'єднання. Дрон підключається, станція слухає. У реальній системі тут радіо або serial; TCP його замінює, кадри ті самі.
- **Станція → Api (заплановано):** багато станцій, один бекенд; кожна станція передає свій `stationId`. Без зв'язку з Api станція тримає останні 10 с телеметрії й досилає їх після перепідключення.
- **Viewer (заплановано):** центральний моніторинг усіх станцій.

Логіка станції живе в бібліотеці (`DeviceLink.GroundStation`), консольна програма — лише тонка обгортка. Пізніше той самий код обгорне десктопний інтерфейс.

## Протокол

Усі числа big-endian.

| Поле | Байтів | Зміст |
|---|---|---|
| Marker | 2 | `AA 55` |
| Length | 2 | довжина payload, максимум 1024 |
| Type | 1 | тип повідомлення |
| Seq | 1 | лічильник відправника, по колу 255 → 0 |
| Payload | N | поля повідомлення |
| CRC16 | 2 | CRC-16/CCITT-FALSE (IBM-3740): poly `0x1021`, init `0xFFFF`, по Length + Type + Seq + Payload |

| Повідомлення | Type | Напрямок | Payload |
|---|---|---|---|
| Telemetry | `0x01` | дрон → станція | lat `i32`, lon `i32` (градуси × 10⁷) |
| Command | `0x10` | станція → дрон | заплановано |
| Ack | `0x11` | дрон → станція | заплановано |

Приклад — 50.4501, 30.5234 (Київ), seq 0:

```
AA 55        маркер
00 08        довжина = 8
01           тип = Telemetry
00           seq = 0
1E 12 13 08  lat = 504 501 000 → 50.4501
12 31 80 50  lon = 305 234 000 → 30.5234
2E 71        CRC16
```

Очікувані байти й CRC у тестах узяті з незалежних джерел (crccalc.com, окремий скрипт), а не пораховані кодом, який тестується. Еталон CRC: `"123456789"` → `0x29B1`.
